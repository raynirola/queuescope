Connect a BullMQ dashboard to private Redis through SSH

Your Redis server can stay on a private network while you inspect BullMQ from your Mac. QueueScope supports SSH tunnels using system OpenSSH and your existing keys or agent.

Know the two endpoints

The SSH host is the machine your Mac can reach, often a bastion. The Redis endpoint is the host and port reachable from that SSH machine. A Redis address that works on your Mac may differ from the address that works from the bastion.

Gather the SSH hostname, port, username, and authentication method; then confirm the Redis hostname, port, database, credentials, and queue prefix with the application configuration. Match the prefix used by your BullMQ producer and workers.

Configure a read-only connection

  1. Install QueueScope and open Connection Manager.
  2. Add the Redis connection details for the intended environment.
  3. Enable SSH tunneling and enter the SSH host and user. Use an existing key or your configured SSH agent.
  4. Use the app's read-only connection option while investigating.
  5. Run connection diagnostics, connect, and discover queues. Compare the discovered queue names with the expected application queues.

The read-only profile controls app actions. Redis permissions are a separate boundary: use the server credentials and ACLs appropriate for your environment.

Keep host and certificate checks

QueueScope uses verified SSH known hosts and retains Redis TLS verification. If the SSH server is unfamiliar or its host key changed, confirm the fingerprint with your infrastructure owner before trusting it. For TLS Redis, use the connection settings your provider requires.

Release builds save Redis credentials in Keychain. Queue data is read from your configured infrastructure; QueueScope does not require a hosted dashboard service to hold those payloads.

If the connection fails

Check the connection diagnostics before changing settings. Separate an SSH authentication failure from a Redis authentication failure. Verify that the bastion can reach the configured Redis endpoint, that the selected Redis database is correct, and that your agent has the intended key.

If you connect successfully but see no queues, check the BullMQ prefix and database. QueueScope targets BullMQ 5.77.x Redis layouts; an empty view alone does not prove that the application has no jobs.

For exact connection fields, use the QueueScope getting-started guide. Once connected, follow the failed-job investigation workflow.
